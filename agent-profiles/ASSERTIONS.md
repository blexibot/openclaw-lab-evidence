# Assertions behind README.md

Each line has four parts: **[kind]** the claim | the evidence file and selector | a one-line check, run from this folder
(`jq` 1.6+, `python3` 3.9+).

**Kinds of check:**
- **[flag]** recounts a flag or verdict that our own grader or summarizer generated (`runs/summary.json`, a row's
  `verdict`, `checks.*`, `info.*`, `scheduler.*`). It verifies the aggregation, not the grading logic; for that, see the
  matching [artifact] check of the grader source or the recorded material.
- **[artifact]** inspects the underlying material: a cell's `openclaw.json`, a `run.log`, `runs/footprints.txt`, the
  gateway-log and request excerpts, the kit source, or the recorded request contents in results.jsonl (session keys,
  tool-call names and arguments, replies). Note that results.jsonl rows are **derived run records** written by the
  grader from the wire capture (tool arguments cut at 4,000 chars), not full captures; the only full request text in
  the packet is the excerpt pair in `excerpts/agents-rule-base-vs-small.txt`.
- **[both]** where one command does both.

**How the checks read the data:**
- Pass counts come from `runs/summary.json`, keyed `"tag|task|rung"`. It counts the latest attempt per label and task,
  the same as RESULTS.md.
- Row-level checks read `runs/<tag>/results.jsonl`. Where a tag had reruns (`q27m-v4b`, `q27m-v4`, `q27m-pr-v4`,
  `q27m-pr-lv4`), the check keeps only the latest attempt per label and task
  (`jq -s 'group_by([.label,.task])|map(max_by(.attempt))[]'`, one file at a time). Checks that read raw rows say why no
  rerun touches them.

**Tags and cohorts:**
- `g-*`: Gemma 4 26B-A4B; `q27m-*`: Qwen 3.8 27B; `q8-*`: qwen3:8b.
- Branch cohort (`ffe3bf0`): `*-pr-v4` fresh workspace; `*-pr-lv4` lived-in; `*-pr-fp` / `*-pr-lfp` first-request
  footprints (fresh / lived-in).
- Release cohort (2026.11.5): `g19-v4`, `q8-v6`, `q27m-v4b` (rungs R0–R3; `q27m-v4b` with the update check off).
- Quarantined, no README claim uses them: `q27m-v4` (2026.11.6 after the model self-updated the install) and `q27m-fp`
  (release footprints; the install was replaced during its R1-s1 turn, so R2-s1/R3-s1 ran after the replacement).
